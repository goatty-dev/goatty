# Wire protocol, client, daemon

- The wire carries raw VT bytes and VT-byte snapshots, never rio-vt types. `Attached` snapshots start with RIS. `Resync` snapshots must not reset, because the client keeps its scrollback.
- Line numbers (v11): rows of a session's primary screen are numbered from the session's start (`Terminal::top_line`). Send `TopLine` after anything that resets or reflows the client's rows (attach, resync, resize), under the subscriber lock so it lands at the right point in the stream. History goes out as `History` replies, never as stream data.
- Compression is per connection (`Compress`, remote clients only) and only for `Attached`, `Resync` and `History` (`encode_server`). Live `Output` stays uncompressed. Flow control counts uncompressed stream bytes.
- Size (v14): only a session's controlling client sets its size; a `Resize` from any other client is only recorded. Send `SizeControl` before `Attached` and before the reflow's `TopLine`, under the subscriber lock. Clients older than v14 take control with every `Attach`/`Resize`.
- Flow control is part of the protocol (adaptive in v15, #9). Clients `Ack` the bytes they consumed. Once a client is past `window`, the daemon skips output and later sends `Resync`. Local subscriptions stay fixed at 8 MiB (`StreamOpts::LOCAL`, lossless, no `FlowControl` attached). Remote subscriptions start at 256 KiB (`StreamOpts::REMOTE`) and adapt per connection across `StreamOpts::MIN_WINDOW..=MAX_WINDOW` (64 KiB..=8 MiB) from `Ack` delivery rate and `ClientMsg::Rtt` (`min_rtt`); the daemon notifies v15 clients of material changes via `ServerMsg::FlowWindow` so they update their `window/4` ack cadence (pre-v15 clients never receive `FlowWindow` and never shrink below 256 KiB).
- Compatibility rules:
  - `Hello` stays variant 0, with `version` as its first field in both enums.
  - Peers negotiate a version in `MIN_PROTOCOL_VERSION..=PROTOCOL_VERSION`.
  - The enums are append-only. Add new variants at the end, never change existing ones, bump `PROTOCOL_VERSION` and mark the variant `vN:`.
  - Neither side sends a message newer than the agreed version.
  - Raise `MIN_PROTOCOL_VERSION` only for a change that can't be appended. Retire a variant in place (a fieldless `Retired…` variant) rather than removing it, so the ones after it keep their index.
  - `Hello`, `ListSessions`, `Restart` and `Shutdown` (and the `Ok`/`Sessions`/`Error` replies) keep their index and fields for good: restarting or stopping goes through `Control::connect_admin`, which still speaks to daemons down to `ADMIN_MIN_PROTOCOL_VERSION` (v10), so a new goatty can replace an old daemon without ending its sessions.
  - Plugin operations go through `goatty_plugin::api` JSON, shell setup and diagnostics through `goatty_shell::setup` JSON (`Shell`, v9), tailnet operations through `goatty_net::api` JSON (`Net`, v12). New operations there need no version bump.
- Encode a broadcast frame once and share it as `Arc<[u8]>`.
- Workspaces (v17, `docs/workspaces.md`): the layout JSON is the client's, opaque to the daemon. Saves are revisioned (a stale `base` gets `Conflict` with the newest layout, never a silent overwrite). `LayoutChanged` goes to the other windows showing a workspace (per connection, `by` names the saver), `WorkspacesChanged` to every connection that listed or joined. A save doesn't make the saver show the workspace; only `JoinWorkspace`/`CreateWorkspace` do. Don't call `Daemon::announce` while holding the `workspaces` lock (it takes it again).
- Don't use `std::io::copy` between pipes and Unix sockets. On Linux it uses `splice()`, which stalled the proxy. Use plain read/write loops, and write binary data to stdout through the raw fd.
- Remote hosts:
  - goattyd is the default and plain SSH the only fallback. Don't add a third mode.
  - Change nothing on a host outside `~/.local/share/goatty` (on a Windows host `AppData\Local\goatty` in the user's profile), and install only after the user agreed.
  - Never restart a daemon in a way that ends its sessions (`stop`, or a daemon older than protocol v10) without telling the user. A `Restart` keeps them.
- The tailnet (`goatty-net`, `docs/tailnet.md`):
  - Use only Tailscale's public CLI, never the LocalAPI. Never install, log in to, or run Tailscale for the user, and never run sudo: show the command instead.
  - In the Serve config, add one route on one port and remove only routes that forward to goatty's gateway socket. Never overwrite another route, and never run `serve reset`.
  - goattyd binds no network socket, not even loopback: tailscaled forwards into the gateway Unix socket. The one exception is Windows, where Serve can't forward into a socket or pipe: the gateway listens on `127.0.0.1` only (`tailscale::Target::Loopback`). Every gateway connection passes the device-key handshake before the protocol.
  - Tests use `crates/goatty-net/tests/fake-tailscale.sh`, never the real `tailscale`.
- The e2e tests in `crates/goatty-daemon/tests/` each use their own `GOATTY_SOCKET` and a sandboxed `HOME`.
- The restore state (`goatty-daemon/src/restore.rs`) is a format between two goattyd builds, like the wire. New fields get `#[serde(default)]`. A change that older builds can't read bumps `STATE_VERSION`, and a restart refuses to hand sessions to a build that reads an older format.
